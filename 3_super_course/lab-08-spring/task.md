# Лабораторная работа
# Разработка REST API на Spring Boot

---

# Цель работы

Научиться разрабатывать backend‑приложения на Java с использованием Spring Boot и создавать REST API для взаимодействия клиента и сервера.

---

# Постановка задачи

Разработать REST API для интерактивного теста или простой игры:

**«(например) Какой ты дистрибутив Linux?»**

Сервер должен:
* хранить вопросы;
* принимать ответы пользователя;
* вычислять результат;
* возвращать результат в формате JSON.

---

# Общая логика приложения

Пользователь:
1. Получает список вопросов.
2. Отправляет ответы.
3. Получает результат теста.

---

# Требования к проекту

## 1. Создание Spring Boot‑проекта

Проект должен быть создан через:
* IntelliJ IDEA;
* Spring Initializr.

---

## 2. Обязательные зависимости

Добавить:
* Spring Web.

---

## 3. Структура проекта

Проект должен содержать:
```
controller
service
model
```

## 4. Реализовать модели

**Модель `Question`**

Должна содержать:
* id вопроса;
* текст вопроса;
* варианты ответа.

**Модель `ResultRequest`**

Должна содержать:
* массив ответов пользователя.

**Модель `ResultResponse`**

Должна содержать:
* название результата;
* описание результата.

## 5. Реализовать REST API

**• GET `/questions`**

Возвращает список вопросов.

**Пример ответа:**
```json
[
  {
    "id": 1,
    "question": "Какой редактор ты выберешь?",
    "options": [
      "vim",
      "nano",
      "VS Code"
    ]
  }
]
```

**• POST `/result`**

Принимает ответы пользователя и возвращает результат теста.

**Пример запроса:**
```json
{
  "answers": [1, 2, 3, 1]
}
```

**Пример ответа:**
```json
{
  "title": "Ubuntu",
  "description": "Ты дружелюбный и универсальный."
}
```

## 6. Реализовать логику теста

**Минимум:**
* 5 вопросов;
* 4 варианта результата.

**Результаты могут быть:**

| Баллы | Результат |
|------|-----------|
| 0–5 | Ubuntu |
| 6–10 | Arch Linux |
| 11–15 | Debian |
| 16+ | Kali Linux |

## 7. Реализовать Service‑слой

**Service должен:**
* хранить вопросы;
* вычислять результат;
* возвращать данные контроллеру.

**Запрещается:**
* хранить всю логику в Controller.

## 8. Тестирование API

**Обязательно протестировать:**
* GET‑запрос;
* POST‑запрос.

**Использовать:**
* Postman;
* или Insomnia.
